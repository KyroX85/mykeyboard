# Project State

## Product

Aritenis is an Android keyboard product with a protected typing foundation and an emerging Phase 2 execution/understanding layer.

## Current Reality

- The keyboard is the product foundation.
- Phase 1 keyboard trust is considered complete enough for transition and is now protected.
- Phase 2 is focused on differentiation, not more keyboard polishing.
- The leading Phase 2 wedge is Explain: helping users understand confusing content before typing.
- WhatsApp agents are the founder-facing operating interface.
- Product Lab and screenshot workflows exist but evidence quality has been unreliable.
- Codex-style agents were added to create long-horizon task discipline: Chief -> Planner -> Executor -> Verifier.

## Protected Foundation

Future work touching these areas requires evidence and strong justification:

- typing feel
- swipe trust
- prediction quality
- keyboard sizing
- layout
- latency
- keyboard stability

## Active Operational Problem

The deployed agents still answer from fragments of context. They can fall back to rigid roadmap templates instead of reconstructing the founder's real product state.

Founder memory must override conversation history and stale reports.

## Source Priority

1. Founder memory files.
2. Current roadmap lock.
3. Product state and rejected directions.
4. Conversation history.
5. Generated reports.

Conversation history must never override founder memory.
