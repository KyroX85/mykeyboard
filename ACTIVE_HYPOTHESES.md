# Active Hypotheses

## H1: Explain Is The Phase 2 Wedge

Users may switch to Aritenis if it helps them understand confusing content before typing.

This is stronger than competing directly with Gboard on prediction, swipe, themes, or settings.

## H2: Screenshot Understanding Is The First Proof Point

The first useful Explain workflow may be:

1. User sees confusing content.
2. User captures or shares screenshot context.
3. Aritenis explains it clearly.
4. Aritenis prepares a reply or action only after confirmation.

No automatic sending.

## H3: Glass Handle May Be The Execution Layer Activation

The preferred activation concept is a subtle glass handle above the suggestion bar.

It should open an action surface without disrupting typing.

This is not implementation-approved yet.

## H4: Product Lab Evidence Must Become Reliable

The agents cannot judge UI or UX quality from black screens, System UI failures, or broken screenshots.

Screenshot evidence must be clean before agents make product recommendations.

## H5: Founder Memory Consistency Is Required Before More Autonomy

If WhatsApp agents cannot reconstruct the product, stage, blocker, and rejected directions, they are not ready for deeper autonomous execution.

## Current Active Hypothesis

Explain is the leading Phase 2 hypothesis, but the founder has not fully locked the 90-day killer feature plan.
